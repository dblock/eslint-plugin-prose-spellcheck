# Design

## Integration

Export a normal ESLint plugin with one report-only rule, `prose-spellcheck/spellcheck`. Usage and configuration are documented in [README.md](README.md).

Traverse native `@eslint/markdown` mdast nodes, not JavaScript ASTs. Join inline prose within each block and map decoded text back to original UTF-16 source spans, preserving locations through emoji, escapes, entities, and multiline containers.

Check prose, headings, visible link labels, and image descriptions. Exclude code, HTML, link destinations, URLs, email, front matter, and matched Liquid spans without skipping surrounding prose.

## Dictionaries

Use public CSpell dictionary and text-extraction APIs with pinned offline dictionaries. Load local dictionary data synchronously during rule creation: the initial scan blocks, but ordinary flat configuration needs no asynchronous setup.

Cache successful package dictionaries by resolved metadata path; retry failed loads. Reread reviewed vocabulary files for each rule instance. Reject remote resources, executable configuration, and invalid data rather than silently falling back.

## Collection

The collector uses the actual ESLint configuration and unsuppressed spelling diagnostics. Abort on other lint errors or selection without an enabled spelling rule. Sort and deduplicate candidates; create output exclusively without overwriting files, changing source, or editing configuration. Optional stdout-only context reports retain each candidate's first source location in lexical path order. Users must review candidates before accepting them.

## Limits

Markdown prose only: no spelling fixes, suggestions, grammar checks, or YAML/source-language checking. Native ESLint still interprets directive comments inside excluded Liquid; preserve the host's suppression behavior.

See [CONTRIBUTING.md](CONTRIBUTING.md) for runtime requirements, validation, and data-driven public API and packed-consumer tests.

## Artwork

The original Dictionary Finch illustration was generated by GitHub Copilot on behalf of @dblock and is covered by the project's MIT license. Retain the transparent raster source `assets/logo-source.png` and white-background display image `assets/logo.png`.

Regenerate the display image with:

```sh
magick assets/logo-source.png -background white -alpha remove -alpha off -strip assets/logo.png
```

Keep the leading README logo at 160 pixels with descriptive alternative text. Check full-size art and light/dark README rendering after changes, then run `npm run lint` and `npm run test:package`.
